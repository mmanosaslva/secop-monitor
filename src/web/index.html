¿Cómo Funciona por Dentro SECOP Monitor?

Explicación detallada de la arquitectura de software, el flujo de procesamiento de datos y la inteligencia de negocio.

El recorrido de cada proceso

01

Extracción Socrata API

Consulta a datos.gov.co mediante SODA API (endpoint p6dx-8zbt.json) usando consultas SoQL con filtros de estado y departamentos.

secop.py
02

Normalización NFD

Elimina acentos, convierte tildes (Unicode NFD), fuerza minúsculas y remueve caracteres especiales para garantizar comparaciones precisas.

engine.py
03

Motor de Filtros

Evalúa coincidencias por departamento, modalidad ("Mínima Cuantía"), palabras clave de objeto y códigos UNSPSC. Detecta badges de preferencia.

FilterEngine
04

Deduplicación SHA-256

Calcula un hash único (SHA-256) sobre el objeto y estado. Evita enviar notificaciones repetidas al cliente mediante la tabla processes en Neon DB.

compute_hash()
05

Notificación Brevo

Construye el correo transaccional en HTML interactivo con badges de color y llamado a la acción. Registra el estado del envío en notifications.

EmailNotification

Cuándo te avisamos

Un proceso SECOP II activa una alerta únicamente si cumple las siguientes 3 condiciones:

  • 1. Ubicación: El departamento de la entidad licitante debe pertenecer a la lista del cliente (ej. Atlántico, Bolívar, Magdalena).
  • 2. Modalidad: Debe corresponder a la modalidad requerida (por defecto Mínima cuantía).
  • 3. Coincidencia de Negocio: Al menos una palabra clave de producto/servicio (ej: "dotacion", "uniforme") O el código UNSPSC coincide exactamente.

Distintivos que detecta

El motor analiza el texto del objeto y la descripción para catalogar automáticamente los criterios de desempate y ley de compras públicas:

Preferencia: Mujer Líder

Detecta empresas lideradas por mujeres o puntaje adicional por género.

PYME Favorable

Identifica convocatorias limitadas a Mipymes según Decreto 1860.

Equidad de Género

Marca incentivos por políticas de equidad de género empresarial.
